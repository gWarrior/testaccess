# Отчёт: связность, удержание контекста, «Хроники Амбера», точность памяти, временные слои

Модель: тернарная HadamRNN, 7 986 176 параметров, 2 трита на вес, d = 256, 3 слоя,
файл `lm/model/model.snnt` (3,2 МБ). SNN-память: окно 300 000 токенов, K/V в тернарном
виде (по умолчанию). Обучение: 1312 шагов на CPU, ~8,6 M токенов прозы на русском языке.
Все прогоны воспроизводимы (`--seed`), команды указаны в каждом разделе.

## Итог в пяти строках

1. **Память точна.** Сама SNN-память, без модели, вспоминает 18 из 18 фактов (книга 1 «Хроник
   Амбера», 108 302 токена, и диалог) и на 5 из 5 выдуманных фраз отвечает «точно нет».
   Время ответа 28–650 мкс.
2. **Модель 8M памятью не пользуется.** Тест «секретного слова» дал 0/9 на всех расстояниях,
   даже на 243 токенах внутри локального окна. Loss ответа ≈ 2,6 одинаков с памятью и без неё.
   Модель выучила *набор* секретных слов, но не само копирование. 1312 шагов для этого мало.
3. **Копирующая голова решает задачу без переобучения.** Добавлена в инференс
   (`--copy λ`, по умолчанию 0,5): если последние 3–8 токенов уже встречались, в кольце
   или в памяти с вердиктом «уверен», модель получает токен, который шёл за ними.
   Точное продолжение на 18 токенов: **0/9 → 9/9 на всех расстояниях от 243 до 300 000**.
   Loss на отложенном тексте тоже падает: 5.0076 → 4.7273.
4. **Временные слои работают, и именно они держат связность.** Без HadamRNN loss 8,34
   (модель разваливается), без retention 5,45, со сбросом состояния между окнами первые
   27 токенов окна дают 5,14 вместо 4,73.
5. **Связность текста слабая.** Грамматика держится на коротких кусках, сюжета нет.
   Для 8M параметров после 3 часов обучения на CPU это ожидаемо. По loss модель лучше
   триграммы (4,73 против 4,76).

## 1. Точность памяти

### 1.1. Память сама по себе (`snn-lm probe`)

шло за ним в тексте (`continuation`), и тернарный вердикт.
Строки с ответом «-» — выдуманные фразы, их правильный ответ «точно нет».

```
snn-lm probe --context amber_book1.txt --probes amber_probes.txt
```

### 1.2. Модель + память: «секретное слово» (`snn-lm recall`)

Ключ («Секретное слово — X.») даётся один раз, вопрос («Какое было секретное слово? —»)
задаётся через D токенов отложенного текста. 9 потоков, засчитывается точный ответ top-1.

| Расстояние, токенов | память ternary | память f16 | без памяти |
|---:|---|---|---|
| 243 | 0/9, loss 2.624 | 0/9, loss 2.625 | 0/9, loss 2.625 |
| 2187 | 0/9, loss 2.575 | 0/9, loss 2.576 | 0/9, loss 2.577 |
| 19683 | 0/9, loss 2.569 | 0/9, loss 2.567 | 0/9, loss 2.584 |
| 177147 | 0/9, loss 2.590 | 0/9, loss 2.589 | — |
| 300000 | 0/9, loss 2.559 | 0/9, loss 2.562 | — |

Loss ответа не зависит от расстояния и от того, включена ли память, ternary или f16.
Модель отвечает «каким-то словом из списка» (≈ ln 13), а не нужным словом.
Вопрос сформулирован иначе, чем ключ, так что здесь нужна *ассоциация*, а её модель
за 1312 шагов не выучила.

### 1.3. Копирующая голова (`snn-lm copyeval`)

Отрывок в 27 токенов встречается один раз. Через D токенов даются его первые 9 токенов,
проверяются следующие 18 (teacher forcing, все 18 должны быть top-1). По 9 отрывков на расстояние.

| Расстояние, токенов | только модель | модель + копирующая голова |
|---:|---|---|
| 243 | 0/9 | 9/9 |
| 2187 | 0/9 | 9/9 |
| 19683 | 0/9 | 9/9 |
| 177147 | 0/9 | 9/9 |
| 300000 | 0/9 | 9/9 |

На 19683 токенах отложенного текста loss **5.0076 → 4.7273** (ppl 150 → 113).
Голова срабатывает на 16.2% токенов и угадывает в 49.6% срабатываний, иначе оставляет
распределение модели нетронутым. Подбор λ: 0,3 → 4,7346; **0,5 → 4,7273**; 0,7 → 4,7453.

### 1.4. Повторное чтение (`snn-lm reread`)

9 отрывков по 2187 токенов из «Хроник Амбера» читаются дважды подряд.

| Память | 1-е чтение: acc / loss | 2-е чтение: acc / loss |
|---|---|---|
| вкл | 0.243 / 5.159 | 0.245 / 5.144 |
| выкл | 0.243 / 5.160 | 0.244 / 5.149 |

Без копирующей головы второе чтение почти не легче первого, то есть модель память не использует.
Так же и на валидации: loss 4,7316 с памятью и 4,7314 без неё.

## 2. Временные слои (`snn-lm ablate --windows 27`)

27 потоков × 27 окон по 243 токена, одни и те же позиции валидации.

| Вариант | loss | ppl | loss по позиции в окне (1-я … 9-я группа по 27 токенов) |
|---|---:|---:|---|
| полная модель | 4.7316 | 113.5 | 4.73 4.74 4.74 4.71 4.75 4.74 4.72 4.70 4.74 |
| без SNN-памяти | 4.7314 | 113.5 | 4.73 4.74 4.74 4.71 4.75 4.74 4.72 4.70 4.74 |
| без состояния между окнами (сброс h, S каждые 243 токена) | 4.8081 | 122.5 | 5.14 4.85 4.80 4.75 4.77 4.76 4.74 4.71 4.75 |
| без HadamRNN | 8.3385 | 4181.9 | 8.37 8.35 8.34 8.32 8.37 8.35 8.32 8.31 8.32 |
| без retention | 5.4521 | 233.2 | 5.43 5.46 5.45 5.44 5.46 5.47 5.45 5.45 5.46 |

- **HadamRNN** — основа модели: без неё loss 8,34, то есть хуже униграммы.
- **Retention** (затухания γ = 1 − 3^−(h+2)) даёт −0,72 нат.
- **Перенос состояния между окнами** (рекуррентный контекст за пределами 243 токенов)
  даёт −0,08 нат в среднем и −0,41 нат на первых 27 токенах окна. Длинный контекст держит
  именно рекуррентное состояние.
- **SNN-память внутри модели** даёт 0,0000. Обученная голова памяти её игнорирует, поэтому
  дальний контекст в модель подаётся через копирующую голову (раздел 1.3).

Для сравнения (те же позиции): триграмма Кнезера–Нея 4,7569, биграмма 5,1754.

## Что дальше

1. **Дообучить копирование в самой модели.** Добавить в корпус эпизоды, где вопрос повторяет
   формулировку ключа, и учить голову памяти на вердикте «уверен». Сейчас голова памяти
   получает градиент только на 1/2187 токенов.
2. **Промах на частых фрагментах.** Расширить бюджет сканирования `locate` для фрагментов
   короче 9 токенов или проверять кандидатов по кольцу позиций n-грамм.
3. **Модель больше и обучение дольше:** связность упирается в 8M параметров и 3 часа CPU.
