# Архитектура проекта

Документ описывает проект целиком: SNN-память (`snn-memory`, корень) и
языковую модель (`snn-lm`, каталог `lm/`). Для каждой части указано:
- что сделано и как;
- какие хитрости и упрощения применены;
- почему выбрано именно так.

Документ — источник правды по архитектуре. Его обновляют вместе с кодом:
правило записано в [CLAUDE.md](CLAUDE.md).

Подробности по отдельным темам:

- [docs/architecture.md](docs/architecture.md) — ядро SNN-памяти подробно;
- [docs/llm-integration.md](docs/llm-integration.md) — API стыковки с LLM;

## 0. Принципы

| Принцип | Как проявляется |
|---|---|
| **Тернарность** | Веса модели — 2 трита (9 уровней), эмбеддинг — 3 трита (27 уровней). K/V памяти — 2 трита. Синапсы SNN — триты. Вердикт памяти — трит. Состояние HadamRNN — опционально 1–2 трита. Шаги квантования — степени двойки, это сдвиг экспоненты, а не умножение. Full-precision обходов нет: где не хватает точности, добавляется трит, а не float. |
| **Степени тройки** | Словарь 3⁸, окно 3⁵, чанк памяти 3³ с шагом 3², ширина K/V 3⁴, батч 3³, память обучения 3¹¹, пороги в девятых долях. Исключение — d = 256: матрица Адамара существует только для порядков 2ᵏ. |
| **CPU** | Обучение и инференс идут на 4 ядрах, без GPU. Отсюда рекуррентная модель вместо трансформера, память вместо O(n²) внимания, свои CPU-ядра. |
| **Точная длинная память** | Контекст 300k токенов. Модель видит его не через сжатое состояние, а через точную SNN-память: чанки, позиции, K/V. |
| **Воспроизводимость** | Движок инференса совпадает с обучающей моделью (тесты до 10⁻³). Возобновлённое обучение совпадает с непрерывным пошагово. |

## 1. SNN-память (`src/`)

### 1.1 Ядро `SnnMemory`

Ассоциативная память на спайковых нейронах: 3⁹ = 19 683 нейрона, каждый
id — один трайт. Каждое воспоминание — отдельная энграмма со своими
синапсами (владение + разреженная аллокация). Поэтому `forget` удаляет
ровно одно воспоминание и не задевает соседей.

- **Энкодеры.**
  - `NGramEncoder` — детекторы совпадений n-грамм для токенов: код фрагмента является подмножеством кода текста, где он встречается, поэтому извлечение по фрагменту точное.
  - `FlyHashEncoder` — тернарная случайная проекция + k-WTA для плотных векторов, без умножений: вес применяется переворотом знакового бита.
- **Синапс = 2 трита** (медленный + быстрый), эффективное значение `clamp(slow + fast, −1, 1)`:

  | Значение | Смысл |
  |---|---|
  | +1 | свидетельство «за» |
  | 0 | молчащий след |
  | −1 | вето |

  Пластичность дискретная (Amit–Fusi): переходы −1 → 0 → +1 с вероятностями. Одно нетипичное предъявление не переписывает память.
- **Извлечение в два этапа.**
  1. Индекс синапсов обходится от редких нейронов к частым в бюджете 3⁹ синапсов (max-score/WAND). Вес нейрона `ln(1 + M/(fan_out+1))` — гомеостаз, аналог IDF.
  2. LIF-аттрактор: достройка паттерна, общий тормозной интернейрон, 9 шагов.

  Кандидатов в аттрактор не больше 27. При равном счёте берутся новейшие энграммы: в длинном контексте шаблонная фраза даёт одинаковый счёт сотням чанков.
- **Тернарный вердикт.**

  | Вердикт | Когда |
  |---|---|
  | `Known` | аттрактор, сходство ≥ 2/9 |
  | `Unknown` | частичные свидетельства |
  | `Absent` | ничто не объясняет даже 1/9 сигнала, либо негативное знание или вето |

  Ложных «уверен» конструкция не даёт.
- **Жизненный цикл.**
  - два банка, быстрый и долговременный; консолидация после 9 извлечений или по `pin`;
  - TTL;
  - контексты;
  - `suppress` (антихеббовское вето);
  - кратковременное облегчение (STP) разрешает ничьи в пользу недавнего.
- **Упаковка.** `TritVec`: 5 трит в байт, 40 трит в `u64`.

### 1.2 `ContextMemory` — память контекста LLM

Окно `max_tokens` (300k на инференсе, 3¹¹ = 177 147 при обучении).

- **Запись.** Токены и K/V пишутся в окно. Каждые 9 токенов (stride) чанк из 27 токенов индексируется одним предъявлением:
  - в лексическую SNN (n-граммы токенов);
  - в семантическую SNN, если она включена: FlyHash среднего ключа первых 9 токенов чанка (страйда) минус центр ключей потока. Центр получает ключи первого страйда каждого чанка в момент его записи, в порядке потока. Поэтому код чанка не зависит от того, какими порциями пришли токены: тренер пишет окно за раз, движок — по 9 токенов. Центр — среднее первых 3⁷ = 2187 ключей, дальше скользящее среднее примерно по стольким же последним ключам: ключи модели дрейфуют всё обучение, и центр, зафиксированный по ключам свежеинициализированной модели, к шагу 486 был почти ортогонален настоящему среднему. Центр хранится в полном снимке. До первых 2187 ключей семантика не пишется и не опрашивается. Нецентрированные средние ключи давали почти одинаковые коды для всех чанков.
- **K/V.** Хранятся в `KvStore` с точностью F32, F16, `Ternary` (absmean + масштаб) или `Trit2`. `Trit2` — 2 трита на элемент плюс показатель степени двойки на строку; хранит 2-тритные K/V модели **точно**.
- **Чтение для модели** (`retrieve_rows`): top-k чанков по зонду (`Probe::Tokens` — токены, `Probe::Key` — запрос, `Both`) → до 81 строки K/V. Модель просит 9 чанков (`MEM_TOP_K`). Если найдено несколько мест, каждое даёт не больше одного чанка строк (27) из своей середины. Иначе три перекрывающихся чанка одного места сливались в участок из 45 токенов и занимали всё чтение: при top-k 3 модель всегда видела ровно одно место. У каждой строки есть позиция и *источник-трит*:

  | Трит | Источник |
  |---|---|
  | 0 | лексический поиск |
  | 1 | семантический |
  | 2 | неиндексированный хвост окна (самые новые токены) |

- **Семантический поиск.** Проба — средний ключ K токенов пробы (того же пространства, что ключи в памяти; запрос `q` головы жил в другом пространстве, и поиск не находил ничего). Порог 1/9, без LIF-динамики, 27 кандидатов; из хитов берутся 3 новейших различных места. Вердикт блока даёт только лексика: семантика при таком пороге почти всегда «уверена».
- **Точные операции без внимания.**
  - `continuation` — что шло после суффикса;
  - `locate` — все позиции фрагмента;
  - `contains` — `Absent` доказывается переписью n-грамм окна.
- **Снимки.**
  - `save_pinned` / `restore` — закреплённые чанки между сессиями.
  - `save_full` / `restore_full` — **всё** состояние: банки с раскладкой, индексы, рабочая память, ГПСЧ, часы, K/V, токены, чанки, перепись. После восстановления любые дальнейшие операции дают те же результаты байт в байт. Окно на 177k токенов весит 24 МБ и сохраняется за ~50 мс. Используется для точного возобновления обучения.

**Упрощения.**
- Нейроны дискретного времени (LIF), без биофизики.
- Консолидация переносит энграмму целиком, без обобщения.
- «Точно нет» для плотных ключей работает только в разреженном режиме; при 300k плотных записях честный ответ — «не знаю».

## 2. Языковая модель (`lm/`)

### 2.1 Общая схема

```text
токены (BPE 6561)
  → эмбеддинг 6561×256, 3 трита (27 уровней), общий с выходом
  → 4 × [ HadamRNN (d=256) | retention (4 головы, ворота swish) | SwiGLU 256→1458→256 ]
  → голова памяти: softmax по
        · локальному окну: 242 предыдущих токена (текущее + прошлое окно),
        · строкам SNN-памяти (до 81 на блок из 3 токенов),
    + эмбеддинг тернарного вердикта памяти
  → логиты словаря
  → pointer-generator: p = a_null·p_vocab + Σ a_j·[токен после j]
```

| Параметр | Значение |
|---|---|
| Параметров | 8 130 196 |
| Слои | 4 × (HadamRNN, retention, MLP) |
| d | 256 |
| MLP | 1458 = 2·3⁶ |
| K/V памяти | 81 |
| Окно обучения | 243 |
| Блок чтения памяти | 3 токена (одно SNN-извлечение на блок) |
| Зонд | последние 9 токенов |
| Память при обучении | 177 147 токенов |
| Память на инференсе | 300 000 токенов |

Конфигурация (`layers`, `mlp`, `state_trits`) пишется в `model.cfg`
прогона, и все команды читают её оттуда.

### 2.2 Квантование весов (`layers.rs::QTensor`)

- **Уровни.** Латентные веса f32 при прямом проходе квантуются в `L·2^round(θ)`:
  - L ∈ {−4…4} = 3·t₁ + t₀ для слоёв (2 трита);
  - L ∈ {−13…13} для эмбеддинга (3 трита).
- **Шаг строки.** Шаг `2^θ` — степень двойки, поэтому умножение на него — сдвиг экспоненты. По умолчанию (`--quant-steps auto`) θ после каждого шага оптимизатора выставляется в MSE-оптимум по текущим латентам: `2^round(log2(0.669·mean|w|))`, для 3 тритов — 0.272, как в BitNet. Так шаг следует за ростом латентов. Показатель целый и меняется с гистерезисом: только когда оптимум ушёл от него дальше чем на 0.6. При простом округлении строки у границы (а строки тензора движутся вместе) сотни шагов переключали шаг туда-обратно. Для EMA показатель пересчитывается из усреднённых латентов, а не усредняется. Раньше θ учился методом LSQ на lr/27 (режим `learned`) и не успевал: латенты за прогон вырастали вдвое, и к шагу 891 в `mlp.w2` и `cell.wu` четверть весов была отсечена.
- **Клиппированный STE.** Внутри диапазона градиент проходит как есть. За пределами проходит только градиент, возвращающий вес внутрь сетки, а толкающий дальше наружу обрезается. Без этого Adam уводил латенты наружу, и доля мёртвых весов росла как √t: 3% на шаге 243, 8% на шаге 729.
- **Контроль в логе.** Каждые 243 шага печатаются доля нулей, доля насыщения, относительная ошибка квантования и доля строк, чей θ ушёл от MSE-оптимума.
- **Хранение.** Экспорт SNNT v2: `Packed::Matrix{levels, exps}`, триты упакованы, показатели степени — i8.

### 2.3 HadamRNN (`layers.rs::HadamCell`)

```text
h_t = round_trits( tanh( h_{t−1} · diag(s)·H·diag(γ) + W_u x_t ) ),   y_t = h_t ⊙ σ(W_z x_t)
```

- `H` — фиксированная ортонормированная матрица Адамара (±1/√d).
- `s` — обучаемые бинарные знаки (STE).
- `γ_j = 1 − 3^−k`, k = 1…5 в пяти группах по d/5 единиц: **фиксированные тернарные затухания** с горизонтами 3…243 токена. Как и в retention, они не обучаются: это тернарные константы, а не параметры.
- **Быстрый скан (хитрость).** `h·R = FWHT(h⊙s)/√d ⊙ γ` — быстрое преобразование Уолша–Адамара за d·log d = 2k операций вместо матмула 256×256. Обратный проход симметричен: `dA·Rᵀ = s ⊙ FWHT(dA⊙γ)/√d`. Скан — одна autograd-операция с ручным BPTT: потоки считаются параллельно, `dR` для знаков берётся одним матмулом.
- **Состояние.** `state_trits` 0/1/2: состояние после tanh округляется до 1 или 2 тритов (уровни ±L/L) со straight-through. В обратном проходе tanh пересчитывается из сохранённого предыдущего состояния.
- **Вход.** `W_u` инициализируется с половинным масштабом (0.5/√d), чтобы tanh не насыщался с первых шагов.

### 2.4 Retention (`layers.rs::Retention`)

- Линейное внимание с затуханием по головам: `S_t = γ_h S_{t−1} + k_tᵀ v_t`, `o_t = q_t S_t`.
- **Затухания** фиксированные тернарные: `γ_h = 1 − 3^−(h+3)`, горизонты 27/81/243/729 токенов. Короткие горизонты покрывает HadamRNN.
- **Параллельная форма** внутри окна (O(T²) с маской затухания), состояние переносится между окнами — стоимость на токен постоянна.
- **Swish-ворота** (как в RetNet): `o ⊙ silu(x·W_g)`, W_g тоже 2 трита.

### 2.5 MLP

SwiGLU `W_2 (silu(W_1 x) ⊙ W_3 x)`, 256→1458→256. Реализован одной слитой
операцией со своим backward (`SwiGlu`/`SwiGluGrad`): меньше промежуточных тензоров.

### 2.6 Голова памяти (`model.rs::Model::head`)

- **Ключ, значение, запрос.** Из нормированного остатка `xn`:
  - ключ `k` и значение `v` — **2 трита** с одним обучаемым общим шагом `2^θ` на K и на V (`quant_shared`, lr/3). Ровно так же `KvStore::Trit2` хранит их в памяти, поэтому обучение видит то, что потом прочитает инференс;
  - запрос `q` — f32 (не хранится).
- **Одна softmax по двум источникам.**
  - **Локально:** каждая позиция видит 242 предыдущих токена — хвост прошлого окна (его K/V хранятся detached) плюс текущее окно каузально. Движок держит такое же кольцо.
  - **Строки SNN-памяти:** retrieval раз на блок из 3 токенов. Зонд — последние 9 токенов, обрезанные по последнему переводу строки, если в текущей строке уже есть 3 токена (`model::probe_of`, одинаково в тренере и движке), плюс запрос `q`. Хвост прошлой строки топил покрытие вопроса ниже порога: «Кто такой N -» находил утверждение «N - мой друг» в 1 случае из 9, с пробой по строке — в 8 из 9 (`examples/probe_line`). Строки, попадающие в локальное окно, маскируются по позиции, чтобы одно и то же не засчитывалось дважды.
- **Вердикт.** Трит вердикта памяти (уверен / не знаю / нет) добавляется в остаток как обучаемый эмбеддинг.

### 2.7 Указатель (pointer-generator)

Колонки указателя — L = 2T + M + 2:

| Колонка | Что копирует |
|---|---|
| прошлое окно (T) | токен, шедший после позиции |
| текущее окно (T, строго раньше) | то же |
| M строк памяти | токен после строки |
| индукционная колонка | продолжение самого длинного недавнего суффикса |
| null | не копирует: её вес — доля словаря `a_null` |

Как устроены колонки:
- **Ключи указателя** — те же 2-тритные ключи памяти. Одна запись в SNN служит и чтению, и копированию.
- **Строки памяти** получают смещения за вердикт блока (`far_verdict`) и за источник строки (`far_source`: лексика / семантика / хвост).
- **Индукционная колонка** — точное продолжение из памяти. Суффикс ищется от 8 до 3 токенов, затем совпадение продлевается до 27. Её логит складывается из признаков:
  - бин длины совпадения (8 бинов);
  - трит числа вхождений (1 / 2–3 / 4+);
  - трит расстояния (в окне / до 3⁹ / дальше);
  - вердикт памяти;
  - `xn·w`;
  - `log p_vocab(кандидат)`;
  - `max log p_vocab`.

  Модель сама учится, когда верить копии.
- **Смесь в лог-пространстве** (`log_softmax` + logsumexp): точна даже там, где вес уходит в denormal. Раньше пол 1e-9 смещал loss.

**Индукция при обучении и на инференсе.**

| Режим | Как ищется продолжение |
|---|---|
| Обучение | точный индекс n-грамм (`train.rs::Induction`: u32-отпечатки, проверка совпадения токенами, обрезка до лимита) |
| Инференс | кольцо 243 + `ContextMemory::locate` (только при вердикте `Known`) |

Признаки одинаковы, это проверяют тесты совпадения.

### 2.8 Потери

- **Основная** — кросс-энтропия смеси (указатель + словарь) по всем токенам.
- **Вспомогательная потеря указателя** — `−log Σ a_j[копирует цель]` с весом `aux` (на фактах ×`aux_fact` = 3: они составляют ~0.7% токенов против ~2.5% у перечитывания). Считается только на токенах ANSWER/REREAD и **только если какая-то колонка держит цель** (`findable`). Без этой маски потеря тянула указатель к равномерному распределению. Шаблонные ответы («не знаю», «мой друг») aux не получают.
- **Контрастная потеря семантической пробы** (`--aux-sem` 1: по весу как один токен ответа в aux указателя). На первом токене каждого ответа-факта проба блока (средний ключ строки вопроса, с градиентом) сравнивается со средним ключом 9-токенного отрезка утверждения из памяти и с 26 другими отрезками: сначала с тем, что семантический поиск принёс вместо утверждения, затем со случайными. Всё центрировано средним самих кандидатов: общая компонента ключей дрейфует при обучении и ничего не различает. Потеря `−ln softmax(cos/τ)`, τ = 1/9. Новых параметров нет: учится тот же `W_k`. Цель — чтобы строка вопроса любыми словами походила на своё утверждение, и семантический индекс находил факт по перефразу, который лексике недоступен.
- **Честное попадание для фактов.** Поток знает, на каких позициях стоит утверждение каждого эпизода (`TaskStream::window_src`, `Src`). Для ответа на факт попаданием aux и `findable` считается только колонка, копирующая **из самого утверждения**, по позиции (`Runner::column_source`). Любой токен с тем же значением не засчитывается: первые слоги имён встречаются повсюду, и прежняя метрика давала 1.000 уже на шаге 27, а aux учила копировать из чужих мест. Потеря смеси по-прежнему засчитывает любую колонку с правильным токеном.

## 3. Обучение (`train.rs`, `data.rs`)

### 3.1 Данные

- **Корпус.** Taiga proza, ~440M токенов, BPE 6561 (`prepare`), отображается в память через mmap.
- **Потоки.** 27 потоков, каждый со своей SNN-памятью на 177k токенов. После каждого документа поток прыгает в случайный документ корпуса, так модель видит все темы.
- **Фильтр стихов.** Если в первых 729 токенах документа больше 1/12 переводов строки, поток прыгает снова: стихи и списки учат переносам строк, а не прозе.
- **Эпизоды на память** (вероятность 1/729 на токен):
  - секретные слова (55 + 2187 выдуманных);
  - один факт о персонаже на отдельной строке: имя, город, кличка питомца или друг;
  - «Кто такой F -» → « мой друг.»: друг оформлен как «Моего друга зовут F. F - мой друг.», так что ответ копируется из утверждения, как любой факт;
  - «Кто такой N -» об имени, которое не называлось, → « не знаю.» — единственный шаблон. Это отдельный эпизод без утверждения, 1/9 всех эпизодов;
  - вопросы теми же словами или перефразом, один вид перефраза отложен для оценки.

  **Однозначность.** Утверждается только спрашиваемый факт. Новый эпизод не начинается, пока открыт вопрос того же типа. Типы: секрет по каждой формулировке, имя, город, питомец по каждому виду, друг, «не знаю» (не больше одного открытого). При пяти типах блокировка отбрасывала 80% эпизодов, и «не знаю» за прогон встречалось лишь ~45 раз. Раньше каждое интро повторяло все факты персонажа, и однозначный ответ был только у ~36% вопросов.

  Дистанция до вопроса — лог-равномерная, до `max_tokens − 486`. Все имена и места выдуманы, реальных наций и топонимов нет.
  Тире в эпизодах — корпусное « - », а не «—», которого в Taiga нет. Вопросы тоже без «?»: в корпусе нет ни одного вопросительного знака, и в эпизодах он стал бы сигналом «сейчас шаблонный ответ». Чат вырезает «?» из ввода. Треть вопросов задаётся словами самого утверждения (их решает индукционная колонка), две трети — перефразом.
- **Перечитывание** (1/2187): отрезок из 27–81 токена, встреченный 243…177k токенов назад, повторяется дословно. Это плотный сигнал «копируй из дальней памяти».
- **Виды токенов.**

  | Код | Вид |
  |---|---|
  | 0 | PLAIN |
  | 1 | ANSWER |
  | 2 | REREAD |
  | 3 | TEMPLATE |

  В логе loss выводится по каждому виду.

### 3.2 Шаг

- **Окно** 243 токена × 27 потоков. Потоки идут группами по `--micro` (3), градиенты групп накапливаются.
- **Параллельные группы.** Группы независимы (свои потоки, память, состояние), поэтому `--parallel` групп считается одновременно; по умолчанию по числу ядер. Градиенты суммируются в порядке групп. Это ×1.7–2 к ток/с: раньше шаг загружал ~1.7 ядра из 4.
- **Порядок в группе:** forward → потери → backward → commit (запись K/V окна в SNN-память, перенос состояния). Граф группы освобождается сразу.
- **Оптимизаторы — пять групп AdamW** (свой `optim::AdamW` с сохраняемыми моментами):

  | Группа | Параметры | lr |
  |---|---|---|
  | `w` | веса | lr |
  | `s` | шаги θ (только `--quant-steps learned`) | lr/27 |
  | `kv` | общий шаг K/V | lr/3 во время разогрева, затем 0 |
  | `head` | скалярные признаки головы: `gate_b`, `gate_verdict`, `ind_*`, `far_*` | 9·lr |
  | `sign` | знаки рекурренции HadamRNN | lr/9 |

  Шаг K/V замораживается после разогрева: пересечение границы округления потом разом удвоило бы шаг всех новых ключей, а в памяти остались бы ключи на старой сетке. Скаляры головы Adam двигает не быстрее lr за шаг, а им нужны единицы натов: в v3 `gate_b` за 891 шаг не сдвинулся с 8.0. Знаки около нуля переворачивались от шага к шагу и меняли рекурренцию. В прогоне с нуля голова стартует с априоров: `ind_len` = 0…7 (чем длиннее совпадение, тем вероятнее верное продолжение), `far_verdict` = [1, 0, −1].

  β₂ = 0.99 (короткие прогоны), клип нормы градиента 1.0, шаги с NaN/Inf пропускаются.
- **Расписание.** Разогрев `--warmup` шагов, затем косинус до **пола 0.4·lr**: при малом lr тернарные уровни замерзают. `--hours` ведёт косинус по времени, чтобы 3-часовой прогон затухал полностью.
- **EMA** латентных весов и шагов (1−1/243, с разогревом горизонта). Сохраняется как `model.ema.safetensors`, все команды берут её по флагу `--weights ema`. EMA-тензоры отсоединены от графа: раньше каждый держал предыдущий, и память росла на 64 МБ за шаг.
- **Валидация** каждые `--val-every` шагов: 9 потоков × 27 окон с памятью, для весов и для EMA. Результат пишется в `val.tsv`, плюс снимок в `snapshots/`.
- **Точное возобновление.** Каждые 81 шаг, на последнем шаге и по SIGTERM/SIGINT (после текущего шага) пишется `resume/`:
  - веса, EMA;
  - моменты и счётчики трёх оптимизаторов;
  - часы расписания;
  - состояния runner-ов: рекуррентные состояния, K/V прошлого окна, позиции;
  - полная SNN-память каждого потока (`save_full`) и индексы индукции.

  Запись идёт через `resume.tmp` → rename. Потоки данных детерминированы по сиду и перематываются до нужного места. Прогон, остановленный и продолженный той же командой, совпадает с непрерывным пошагово.

### 3.3 Сборка и скорость

- `scripts/build-native.sh` собирает с `-C target-cpu=native` (AVX-512 и т.п.) в `target/native`, это +8%.
- **Своя CPU-арифметика:**
  - слитые softmax/CE со своим backward (у candle 0.9 `softmax_last_dim` без backward);
  - фьюзд-SwiGLU;
  - скан HadamRNN через FWHT;
  - квантование как CustomOp.

## 4. Инференс (`infer.rs`, `pack.rs`)

- **Формат.** SNNT v2: триты весов плотно упакованы, показатели степени шага — i8, конфигурация модели в заголовке.
- **ShiftLinear — умножение без умножений.** Входы группируются по уровню веса: суммы по +k и −k, затем умножение на малые целые k (сдвиги и сложения), затем шаг строки 2^e — это сдвиг экспоненты.
- **VNNI (`--features vnni`).** Веса хранятся как int16. Вход раскладывается на старшую часть int16 и остаток int16 (~30 бит), две `vpdpwssd` на строку, суммирование в i32. Ошибка ≤ 1e-6, скорость ×7–21. Наличие VNNI проверяется во время работы.
- **HadamRNN** шагом FWHT; retention в рекуррентной форме.
- **Кольцо.** Держит до 251 токена с K/V, внимание идёт по последним 243. Токены уходят в SNN-память по 9 — шаг чанка: так каждый токен памяти принадлежит чанку, как при обучении.
- **Ответ не копирует сам себя.** `reply_start` запрещает указателю и индукции колонки внутри текущего ответа.
- **Декодирование чата** (`Parts`/`Decoding`). Движок отдаёт словарь, гейт и копии указателя отдельно.
  - Температура и top-p действуют только на словарную часть, поэтому найденный указателем факт не размывается.
  - Штраф за токены, уже встречавшиеся в ответе. Короткие служебные токены (до 2 букв: « я», «,», « и») штрафу не подлежат, иначе ответы вырождались в «я, я, я». В режиме диалога ответ обрывается на «, -»: в корпусе после этого идёт авторская ремарка («, - сказал он»). Запрет повторять любую 4-грамму, которую модель уже сказала в этом диалоге (включая стык с репликой собеседника): так она не копирует свои прошлые ответы.
  - Жёсткая индукционная копия с весом по длине совпадения: 0 при длине до 2, полный вес при 8+.
  - Реплики в формате корпуса: «- реплика\n-». В Taiga нет длинного тире, и BPE его не слил, это 3 сырых байта. Пробел после «-» не подаётся: BPE клеит его к следующему слову.
- **Совпадение с обучением.** Тесты сравнивают движок с обучающей моделью (до 10⁻³, для 0/1/2 тритов состояния), в том числе на нескольких окнах подряд с памятью.

## 6. Сознательные упрощения и известные ограничения

- **Запрос `q` в f32.** Запрос головы памяти и активации между слоями — f32. Тернарные только веса, K/V и опционально состояние: активации не хранятся.
- **Размер модели.** d = 256 и ~8M параметров зафиксированы: модель учится на CPU за часы. Качество прозы ограничено размером; цель — рецепт, который масштабируется.
- **Выбор чанков.** SNN выбирает чанки как stop-gradient top-k (как Memorizing Transformers). Градиент идёт в чтение, а не в выбор.
- **Устаревание ключей.** Ключи в памяти посчитаны старыми весами. Внутри 3-часового прогона это допустимо.
- **Детерминизм.** Инициализация candle на CPU не сидируется. Воспроизводимость между прогонами — через `--init`; внутри прогона — точная через `resume/`.
- **Ассоциативные вопросы** («кто друг N») пока решаются плохо. Это открытая задача рецепта.
